# 项目复盘总结 
项目名称：lab1_task2_fastapi_bookkeeping 简易记账FastAPI接口实验

## 一、AI协助完成内容
1. 仓库命名、项目目录结构规划，Gitee仓库文件组织方案设计
2. FastAPI业务代码编写：路由接口定义、Pydantic模型设计、SQLite数据库初始化与连接代码
3. 代码警告修复：将过时`@app.on_event("startup")`改造为`lifespan`生命周期写法，消除运行DeprecationWarning警告
4. 运行问题排查：requirements文件缺失报错、首页404问题、服务启动日志解读
5. 配套文档模板生成：README、需求澄清文档、AI协作记录文档、.gitignore模板
6. pytest测试用例编写思路，边界异常测试场景设计

## 二、人工决策与确认内容
1. 实验需求理解：确定接口清单，人工确认不需要实现修改、删除接口，满足考题要求。
2. 业务规则敲定：记账流水字段定义；收支汇总逻辑，收入减去支出得到结余；分页参数校验规则人工确认。
3. 风险审查
    - 风险1：代码使用字符串拼接构造WHERE条件，存在SQL注入隐患。人工评估：本项目为课程实验，仅本地单机运行，不对外暴露，作业场景可接受；生产环境需改用安全方式构建动态SQL。
    - 风险2：数据库bookkeeping.db不提交至代码仓库，项目启动自动建表，老师拉取代码可自动初始化，人工确认该交付方案。
    - 风险3：接口采用同步def定义，人工确认FastAPI原生支持同步接口，满足实验要求。
4. 人工本地完整测试全部接口，验证新增、筛选分页查询、收支汇总功能正确性，确认 `/docs` 接口文档可正常访问。
5. 确认全部交付物清单，整理源码、文档、测试结果，核对仓库提交内容。

## 三、整体复盘
AI负责基础框架搭建、代码编写、报错调试、文档模板生成，节省环境搭建与基础编码时间。
业务需求取舍、代码风险审查、功能验收测试全部由人工完成。AI产出代码必须人工阅读、本地运行校验，不能直接提交。本次实验借助AI提升开发效率，同时保持人工对项目整体的把控。
